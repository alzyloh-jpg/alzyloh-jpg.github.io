Day 2

Dual-arm teleoperation and imitation-learning workflow, plus 3D modelling for block-picking experiments.

Full process for the VR dual Nero arms

The notes describe two related workflows: a VR-driven dual-arm ACT pipeline, and a direct SO-101 leader-to-Nero follower setup. Keep the arm clear of people and use the manufacturer's safety procedures when testing any motion.

Dual-arm visuomotor imitation-learning pipeline

1. Real-time bus topology and hardware abstraction

The system uses two independent CAN 2.0B interfaces: can0 for the right manipulator and can1 for the left. The notes specify 1 Mbps. At a theoretical 128 bits per frame, the raw upper bound is about 7.8 thousand frames per second per bus before accounting for protocol efficiency and overhead.

sudo ip link set can0 up type can bitrate 1000000
sudo ip link set can1 up type can bitrate 1000000
ip -br link show type can
ros2 launch lerobot_agx_adapter nero_dual_bringup.launch.py

Initializing the interfaces connects Linux SocketCAN to the physical transceivers. The ROS 2 hardware abstraction exposes joint positions and velocities for the two manipulators.

2. Spatial calibration and zero point

The workstation and Pico VR headset first establish a low-latency local network. Kinematic calibration then determines the mapping from joint positions to the end-effector pose for each arm. The notes describe each joint using a screw axis, a home configuration, and an encoder-offset vector; calibration writes offsets, transformations, and joint limits into nero_dual.yaml.

hostname -I
conda activate lerobot-dual-arm
CFG=$HOME/Workspace/dual-arm/configs/profiles
arm-teleoperate \
  --config_path=$CFG/nero_dual.yaml \
  --calibrate_write=true

3. VR teleoperation and demonstration capture

The operator's two 6-DOF VR hand poses are mapped into robot task space using differential inverse kinematics. Three Intel RealSense RGB-D cameras capture multi-view observations at 30 Hz. The described dataset contains 20 “pick and place” demonstration episodes, pairing observations and joint states with target actions.

conda activate lerobot-dual-arm
export NERO=$HOME/Workspace/dual-arm
export CFG=$NERO/configs/profiles/nero_dual.yaml
export TASK=nero_task4NovTest3
lerobot-record-vr \
  --config_path=$CFG \
  --robot.cameras="$CAMS" \
  --dataset.root="$NERO/outputs/datasets/$TASK" \
  --dataset.repo_id=local/$TASK \
  --dataset.num_episodes=20 \
  --dataset.single_task="pick and place" \
  --dataset.push_to_hub=false \
  --display_data=true

4. ACT policy training

ACT predicts a sequence of actions conditioned on the current camera observations and joint state. The notes describe a conditional variational autoencoder: an encoder represents the demonstrated action sequence as a latent style variable, and a Transformer decoder reconstructs the actions. Training minimizes action error plus a weighted KL-divergence term.

lerobot-train \
  --dataset.repo_id=local/$TASK \
  --dataset.root="$NERO/outputs/datasets/$TASK" \
  --policy.type=act --policy.device=cuda \
  --steps=60000 --batch_size=8 \
  --output_dir="$NERO/outputs/models/$TASK" \
  --job_name=act_$TASK \
  --wandb.enable=false \
  --policy.push_to_hub=false

5. Autonomous evaluation and temporal ensembling

For evaluation, VR teleoperation is disabled and the policy runs closed-loop using camera input. The notes use a 50-action prediction horizon and exponential temporal ensembling to combine overlapping predictions, favoring newer visual feedback while smoothing motion.

lerobot-record-vr \
  --config_path=$CFG \
  --teleop=null \
  --policy.path="$NERO/outputs/models/$TASK/checkpoints/last/pretrained_model" \
  --policy.n_action_steps=50 \
  --robot.cameras="$CAMS" \
  --dataset.root="$NERO/outputs/eval/eval_$TASK" \
  --dataset.num_episodes=10 \
  --dataset.single_task="evaluate pick and place" \
  --dataset.push_to_hub=false \
  --display_data=true

SO-101 leader and Nero follower workflow

The following commands and mapping were included in the notes for a separate direct teleoperation setup. Confirm the correct hardware, ports, calibration, and emergency-stop procedure before use; test in dry-run first and do not assume these paths or device names match another machine.

1. Environment setup

conda activate nov-smallarm-2026
pip install feetech-servo-sdk python-can pyyaml rich pynput
pip install "pyAgxArm @ git+https://github.com/agilexrobotics/pyAgxArm.git"
cd ~/Desktop/NovSmallArm2026
pip install -e src/lerobot_plugins/robot_agilex_nero --no-deps
pip install -e src/lerobot_plugins/teleop_so101_leader --no-deps

Purpose given in the notes: activate an isolated Python environment and install motor drivers and local plugins so edits in the workspace are picked up immediately.

2. Terminal initialization

unset PYTHONPATH
conda activate nov-smallarm-2026
export LD_LIBRARY_PATH="$CONDA_PREFIX/lib:$LD_LIBRARY_PATH"
cd ~/Desktop/NovSmallArm2026

This clears conflicting global Python paths and prioritizes the environment's shared libraries.

3. Hardware ports and diagnostics

sudo ip link set can0 down
sudo ip link set can0 type can bitrate 1000000
sudo ip link set can0 up
sudo chmod 666 /dev/ttyACM0

python src/scripts/test_so101_reader.py --port /dev/ttyACM0
python src/scripts/test_nero_can.py --channel can0 --firmware v120

The notes use these tests to check each arm independently before linking them. Device permissions and interface configuration should be set only on the intended machine and hardware.

4. Calibration and axis alignment

python src/scripts/calibrate_nero.py --channel can0 --firmware v120
python src/scripts/align_teleop_axes.py --port /dev/ttyACM0

Calibration records corresponding resting poses and checks joint direction. Relative teleoperation sends displacement from the starting pose, intended to avoid a sudden jump when control begins.

5. Teleoperation

python src/scripts/teleop_direct.py --port /dev/ttyACM0 --channel can0 --dry-run
python src/scripts/teleop_direct.py --port /dev/ttyACM0 --channel can0 --speed-percent 10

The notes describe dry-run as a terminal-only mapping test, and the second command as live control at 10% maximum speed. They mention Space to pause/resume and Esc or q for a software stop. A software stop is not a substitute for the physical Emergency Stop.

3D modelling for ideation

Test blocks of different sizes were printed to find a suitable scale. A base structure was also designed to hold the blocks so the Nero arms could pick them up more easily.

Takeaways: learning to use 3D printers, becoming familiar with CAD software, and learning how to use slicing software.

PrusaSlicer: modelling a blueberry

  1. Create the berry body: add a sphere and use the Scale tool to slightly squash its Z axis. Unlock the scale axes first to make a natural-looking berry rather than a perfect ball.
  2. Carve the crown cavity: add a negative cylinder or sphere, scale it to about 30% of the berry's width, center it at the top, and push it slightly into the surface.
  3. Build the calyx: add a torus or small cylinders/cones angled outward around the cavity. Overlap the parts with the body so they form one printable mesh.
  4. Add organic texture: in Advanced or Expert print settings, set Fuzzy skin to Outside walls. The notes suggest 0.1 mm thickness and 0.3 mm point distance.
  5. Smooth and slice: use Variable layer height, then Adaptive and Smooth. Enable Organic supports on the build plate, slice, and export G-code.
